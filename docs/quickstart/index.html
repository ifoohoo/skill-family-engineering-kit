    快速开始¶

    第一次本地验证¶

    pnpm install
pnpm synth
pnpm check

    pnpm check 退出码 0 即统一根门禁全部通过：稳定门禁 ID 按固定顺序串联执行。逐 ID 清单与产品级当前状态见 当前产品状态。

    接手开发¶

    1. 完整读取根级 AGENTS.md（工程约定）与 Git 生命周期指南（Git 写操作的授权边界）；
    2. 只修改当前任务授权的写集，不顺手修改无关文件；
    3. 运行任务指定的验收命令和根 pnpm check，记录退出码；
    4. 汇报证据、剩余风险和未执行的外部动作（commit、push、发布等默认全部不执行）。

    不要把当前的种子 JSON 当作正式 Contracts，也不要在一个任务里同时实现 Contracts、Harness、Kit、审计和迁移。

    试运行 Kit 四命令¶

    安装 Kit 包（skill-family-engineering-kit 的发布包或本地打包产出的 tarball）后，稳定入口是该包登记的 bin（指向 src/cli.mjs）；默认许可证 Profile 随包闭包解析，无需 --profiles-root：

    # 在空目录生成完整项目骨架（目标必须为空，写入全部原子且受路径收容）
npx skill-family-engineering-kit scaffold --root ./demo-project --project-id demo-project

# 对骨架目标做诊断（退出码 0 = 无发现）
npx skill-family-engineering-kit check --root ./demo-project

# 对存量仓做严格只读的采用规划（不写任何文件，计划输出到 stdout）
npx skill-family-engineering-kit adopt-plan --root .

    本 monorepo 内也可等价使用 node packages/skill-family-engineering-kit/src/cli.mjs <command>；总帮助（恰好四个顶层命令及各自的副作用声明）用 --help 查看。

    退出码约定：0 成功或无发现；1 check 有发现；2 拒绝、用法或机制错误。错误消息携带已注册的 SFC 错误码。命令副作用与诊断分类详见 能力与诊断。

    消费坐标¶

    三个叶子包（skill-family-contracts、skill-family-harness-node、skill-family-engineering-kit）经 npm 与对应的 public 发布镜像分发。发布镜像不承载完整开发历史与测试，也不接受直接 PR；钉住的消费坐标与当前发布状态唯一记录在 当前产品状态。

    文档自检¶

    修改文档后运行：

    node scripts/docs/fact-check.mjs
node scripts/docs/link-check.mjs

    事实检查对照机器真源（manifest、package.json、Contracts 登记、版本锁与工作流），链接检查解析全部站内相对链接与锚点。
