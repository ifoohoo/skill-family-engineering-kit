    能力与诊断¶

    产品级的当前状态只在唯一状态页 当前产品状态 声明（由 node scripts/docs/fact-check.mjs 对照机器真源机械校验）；本页正文不复制任何动态状态口径。仓内检查的诚实边界：manifest、package.json、门禁脚本与工作流等结构检查只证明“字节/结构一致性（仓内可证）”；自然语言语义的正确性不属于仓内正则或摘要可证明的范围，需外部独立审阅。

    当前能做什么¶

    • projen 受管文件的合成（pnpm synth）、只读漂移检查（pnpm drift）与幂等性验证（pnpm synth-idempotency）；
    • Contracts v1 校验：六类顶层对象、协议名登记、SFC 错误码体系、13 条强制机械规则（预算不超过 20 条，绝对上限 30 条）；
    • Harness 机制：原子写、路径与符号链接收容、资源闭包、临时工作区、kernel 请求处理；
    • Engineering Kit 四命令（见下节），全部不执行 Git 写操作、发布或删除；
    • 稳定产品门禁（pnpm check 串联，逐 ID 见 当前产品状态）；
    • 发布字节合同：pnpm run release-artifacts:build 与 pnpm run release-artifacts:verify（见 当前产品状态）；
    • 公开静态站渲染：node scripts/render-public-site.mjs（冻结 MkDocs 环境 strict 构建、内容泄漏扫描与确定性基线；--write / --check / --self-test）；
    • 文档事实/链接检查（node scripts/docs/fact-check.mjs、node scripts/docs/link-check.mjs）。

    当前不能做什么¶

    • 不提供发布、部署或远端写入的命令能力；发布与部署的当前状态见 当前产品状态；
    • 没有第五个 Kit 顶层命令；check 只诊断、绝不自动修复；
    • 不做多宿主投影、Python 对称运行时或第二套模板引擎（首版禁止扩张项）。

    Kit 四命令与副作用¶

    CLI 入口：packages/skill-family-engineering-kit/src/cli.mjs。恰好四个顶层命令：

    命令 作用 副作用边界
    scaffold 在空目录生成 Skill Family 项目骨架 只向空目标目录写入骨架文件（原子写、路径收容）；非空或冲突目标被拒绝且不被触碰
    adopt-plan 严格只读地规划存量仓采用 无——不写任何文件（含临时文件），不运行 Git 写命令；计划输出到 stdout
    projection 投影受管生成物 只写 manifest 授权且被目标声明为受管的路径；未授权、手写或越界路径一律拒绝（拒绝时零写入）
    check 契约/漂移/闭包/版本/文档事实/Git 前置状态/许可证身份诊断 无——只诊断、绝不自动修复；Git 仅只读探测

    退出码：0 成功或无发现；1 check 有发现；2 拒绝、用法或机制错误。每次拒绝都打印已注册的 SFC 错误码和稳定 kind。--fix、--apply 等变更模式标志在入口处被拒绝（退出码 2）。

    check 的七个诊断类¶

    check 命令按类报告发现，可用 --only <class> 单独运行一类：

    类 检查内容
    contracts 发现的契约文档是否通过已登记 Schema 校验
    drift managed-file-lock 条目与磁盘实际字节是否一致
    closure 声明输入/输出的资源闭包是否完整
    version 声明的 Contracts 版本与冻结版本是否一致
    docs 文档事实（README 存在性、身份一致性）
    git 只读 Git 前置状态（绝不执行 Git 写）
    identity 许可证 Profile 与身份防漂移（机器身份记录为权威）

    故障排查¶

    • 命令失败时先确认 Node、pnpm 与锁文件一致（见 安装与环境），再运行 pnpm synth；不要手改 projen 生成文件来绕过失败；
    • Git 写操作的授权边界唯一见 Git 生命周期指南；未获针对当前任务的显式授权时不得执行任何 Git 写操作；
    • pnpm check 失败会打印具体门禁与路径；按提示修复根因，不得为转绿放宽检查或修改独立预期值；
    • 并行开发时若疑似资源抢占导致偶发失败，稍候重试一次再下结论；
    • 文档站点构建失败时优先核对 scripts/docs/requirements.txt 是否与 scripts/docs/toolchain.json 一致（node scripts/docs/fact-check.mjs 会校验）。
